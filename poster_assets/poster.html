Self-Generated Curricula via Joint Conjecturer–Prover RLOO
for Arithmetic Reasoning

Finn Stäblein  •  Stanford CS 224R, Spring 2026  •  Default Project Extension: Self-Play & Multi-Agent Co-evolution  •  Qwen 2.5-0.5B on Countdown

The Problem

RL fine-tuning of reasoning LLMs is bottlenecked by a static curriculum: once the model has consumed its training set, the learning signal runs out. But for tasks with a cheap, rule-based verifier, fresh signal can be manufactured at will.

Countdown: given numbers [44 19 35] and target 98, produce an expression using each number once that evaluates to the target. A 12-line Python verifier checks any candidate — no reward model needed.

Question: Can a small model generate its own problems, targeted at its current frontier of ability, and keep improving without human-annotated data?

Method — Two Co-evolving Policies

Two copies of the SFT model, both trained online with RLOO (REINFORCE leave-one-out):

  • Conjecturer (C) generates new problems.
  • Prover (P) attempts to solve them.
  • C is rewarded when P solves its problems at the right difficulty — neither trivial nor impossible.
1. Sample C → N candidate problems 2. Parse (numbers, target) 3. Solvability filter (brute force) 4. Build prover prompts (+ real data) 5. Sample P → k rollouts / problem 6. Score P (verifier + len penalty) 7. C reward from P's solve-rate p̂ 8. RLOO update P 9. RLOO update C

Two tricks that made it work:

  • Completion-mode prefill. The SFT model is so drilled on solving that asking it to write a problem triggers solve-mode. Ending C's prompt with <problem> numbers=[ forces the first token to be a digit — parseable rate 25% → 95%.
  • Shaped difficulty reward. rC = max(0, 1 − 2.5·|p̂ − 0.4|): a tent peaking at a 40% solve-rate, giving C a gradient back toward the frontier instead of a binary on/off band.

Why It Beats RLOO

FAILURE ANALYSIS

What Breaks When You Scale Naively

Scaling v6 to 64 problems/step, 100 steps, c-lr 1e-5 (v7) looked like a win — prover training accuracy climbed to 1.0 — but the test set exposed three coupled failures:

  • Curriculum collapse. P got so strong it solved everything C produced (p̂→1.0). The binary reward then paid 0 on every problem → leave-one-out advantage 0 → C's gradient died and never recovered.
  • Diversity collapse. P mode-collapsed onto C's narrowing distribution: pass@16 fell 0.80 → 0.62, worse than the untrained SFT model.
  • Eval truncation. 34% of v7's test responses hit the token cap mid-reasoning and never emitted an <answer> — a measurement artifact masquerading as a capability loss.
FIXES (v9, RUNNING)

Recovering the Win at Scale

  • Shaped tent reward — gradient survives even when C drifts off-target.
  • 50/50 real-data mixing — half of P's problems come from the fixed set, so the method degrades gracefully to RLOO and protects coverage.
  • Length penalty + 2048-token eval — removes the truncation artifact.
  • Stabilized C (lower lr, firmer KL anchor) + frequent checkpoints with best-of-step selection.

Live collapse monitors (c/p_hat_mean, c/frac_too_easy) now make the v7 failure mode visible in real time.

Takeaway. Where verification is cheap — math, code, constraint satisfaction — a 0.5B model can manufacture its own curriculum and recover the exploration that on-policy RL throws away. The conjecturer/prover loop turns a static dataset into an open-ended one, with ~75× less policy-gradient data than vanilla RLOO.
